# Offline player horizontal facing input

The attached [High P-code rows](player-horizontal-facing-pcode.tsv) were exported from the already analyzed user-owned Nevergone 1.0.9 ARMv7 `libcocos2dcpp.so` (SHA-256 `94b1ef6a9469e261183ac08199c5b0eb65c0c40b81918ca097bd32920828eb5e`) with `ExportFunctionPcodeFlow.java`. Ghidra addresses are ELF offsets plus `0x10000` in this project.

At Ghidra `0x0032de36`, `MEPlayer::setControlsState` compares its input with `0x12`, and at `0x0032de44` calls `MEPlayer::filpPlayer` with `true`. At `0x0032de50`, it compares with `0x13`, and at `0x0032de60` calls the same function with `false`. `MeActionsSystem::filpAction` stores the boolean at `+0x1be` (`0x0033910c`) and passes it to `CCSprite::setFlipX` on its primary sprite at `+0x118` (`0x00339114`). These are derived control-flow facts, not original binary or source assets.

The project-owned Android input adapter captures one drag starting in the lower-left part of the viewport. It normalizes horizontal displacement by viewport width and feeds the sample into the existing `player_control_runtime_state`, which applies the already recovered `0.05` activity threshold. A drag toward negative X maps to the `0x12` hemisphere and `flipX=true`; a drag toward positive X maps to `0x13` and `flipX=false`. The adapter keeps the last facing after release and resets it when the scene changes. The existing render-queue bridge changes only the body sprite's flip flag. Its touch area and normalization are temporary offline UI choices; no original joystick geometry is claimed.

This provides a visible state change when the selected player action document and atlas bitmap exist in imported user data. The local OBB inspected for the first sprite still lacks the referenced `p01_i01.actData`, and no Android device is connected here, so an on-device visual capture remains outstanding. The next combat slice needs its own evidence for movement, action transitions, and enemy interaction; this input boundary does not infer those behaviors.
